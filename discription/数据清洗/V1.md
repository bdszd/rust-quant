# Data Clean V1 — 行情数据清洗模块

## 1. 模块定位

Data Clean 是量化回测系统中的行情数据处理模块，负责将外部数据源获取的原始行情数据，转换为系统内部统一、规范、可供回测引擎使用的标准行情数据。

外部数据源提供的行情数据通常具有以下特点：

- 不同数据源的字段名称和数据格式可能不同。
- 日期格式可能与系统内部格式不一致。
- 成交量、成交额等字段的计量单位可能不同。
- 原始数据可能存在缺失、格式错误、重复记录或异常行情。

因此，系统需要一个独立的数据处理模块，在原始行情进入回测引擎之前完成解析、校验、标准化、清洗和持久化。

**核心职责：**

将外部原始行情转换为系统内部统一的 `Bar` 数据结构，并提供数据质量统计及持久化能力。

## 2. 核心功能

### 2.1 原始行情数据解析

负责读取外部数据源提供的 CSV 文件，将原始文本记录转换为 Rust 数据结构。

当前版本支持 Tushare 日线行情 CSV。

原始数据字段：

| 字段         | 含义   |
| ---------- | ---- |
| ts_code    | 股票代码 |
| trade_date | 交易日期 |
| open       | 开盘价  |
| high       | 最高价  |
| low        | 最低价  |
| close      | 收盘价  |
| pre_close  | 昨收价  |
| change     | 涨跌额  |
| pct_chg    | 涨跌幅  |
| vol        | 成交量  |
| amount     | 成交额  |

内部使用 `RawTushareBar` 表示原始行情记录。

Parser 负责：

- 读取 CSV Header。
- 按字段名称解析数据。
- 将数值字段转换为对应的数值类型。
- 保留无法正常解析的记录及错误信息。
- 将解析结果交给 Cleaner 进一步处理。

解析结果使用 `ParsedTushareRow` 表示：

| 字段 | 含义 |
|---|---|
| row_number | 原始 CSV 记录序号 |
| ts_code | 股票代码 |
| trade_date | 交易日期 |
| raw | 解析成功后的原始行情 |
| parse_error | 解析失败原因 |

通过这种设计，单条记录的字段解析错误不会直接导致整个清洗流程终止。

**当前责任边界：
1.读取到无法解析的行，row字段会返回None，继续循环读取下一行，但不代表CSV解析器一定能从语法错误中恢复。
2.原始数据无法按照制定的数据结构规则反序列化时，row字段会返回None。
3.其余情况会按原始数据值解析，数据合法性交由后续模块验证。

### 2.2 行情数据校验

负责检查原始行情是否符合基本的数据规范。

当前主要检查：

**基础字段检查**
- 股票代码不能为空。
- 交易日期必须符合 YYYYMMDD 格式，并且是有效日期。
- OHLC 和成交量等必需字段必须存在。

**价格检查**
- OHLC 价格必须是有限数值。
- 价格必须大于零。
- 最高价不能低于开盘价、收盘价和最低价。
- 最低价不能高于开盘价、收盘价和最高价。

**成交数据检查**
- 成交量不能为负数。
- 成交额不能为负数。

**可选字段检查**
- 昨收价必须大于零。
- 涨跌额、涨跌幅必须是有限数值。

基础校验失败的记录不会进入标准行情数据集，而是被记录为 RejectedRecord。

### 2.3 行情异常检查

在基础合法性检查通过后，对行情进行进一步的异常检测。

当前检查：

- 单日涨跌幅异常。
- 日内价格振幅异常。
- 成交量为零。

与基础校验不同，异常检查采用 Warning 机制。

例如，某只股票单日上涨 35%，这不一定意味着行情数据错误，也可能是特殊市场事件或公司行为导致的真实价格变化。

因此：

- Reject：数据不符合基本规范，不进入清洗后的行情数据集。
- Warning：数据结构合法，但存在值得关注的异常，保留行情并记录警告。

这种设计可以避免将真实市场行情误判为错误数据。

**当前责任边界：
1.对一条rust格式的行情数据进行有效性判断，判断规则见上述。
2.后续需对涨跌幅规则进行区分，而不是统一进行简单判断。

### 2.4 数据标准化

负责将外部数据源的字段格式和计量单位转换为系统内部统一标准。

当前内部标准：

| 字段 | 内部格式 | 单位 |
|---|---|---|
| symbol | 股票代码 | 字符串 |
| date | YYYY-MM-DD | 日期字符串 |
| open | f64 | 元 |
| high | f64 | 元 |
| low | f64 | 元 |
| close | f64 | 元 |
| volume | f64 | 股 |
| amount | Option<f64> | 元 |

当前 Tushare 数据单位转换：

| 原始字段 | 原始单位 | 内部单位 | 转换方式 |
|---|---|---|---|
| open/high/low/close | 元 | 元 | 不转换 |
| vol | 手 | 股 | × 100 |
| amount | 千元 | 元 | × 1000 |

日期由：

```text
20240102
```

转换为：

```text
2024-01-02
```

标准化后的数据使用系统内部的 `Bar` 结构表示。

### 2.5 数据清洗与去重

Cleaner 负责组织整个数据清洗流程。

主要工作：

1. 接收 Parser 返回的解析结果。
2. 处理解析失败记录。
3. 调用 Validator 检查基础合法性。
4. 调用异常检查函数生成 Warning。
5. 调用 Normalizer 转换为标准 Bar。
6. 检查重复行情。
7. 将合法行情和拒绝记录分别保存到结果中。
8. 对行情按照股票代码和交易日期排序。

当前去重规则：

```text
symbol + date
```

同一只股票在同一个交易日只能保留一条行情记录。

不同股票在同一天的行情不会互相影响。

### 2.6 数据质量统计

Quality 负责统计整个清洗过程中的数据质量。

当前提供以下指标：

| 指标 | 含义 |
|---|---|
| total_rows | 原始数据总记录数 |
| accepted_rows | 接受的记录数 |
| rejected_rows | 拒绝的记录数 |
| duplicate_rows | 重复记录数 |
| warning_rows | 存在异常警告的记录数 |
| rejection_reasons | 各种拒绝原因的出现次数 |
| warning_reasons | 各种异常警告的出现次数 |

清洗完成后，可以通过 `DataQualityReport` 获取整体数据质量情况。

### 2.7 数据持久化

Storage 负责保存清洗结果，避免每次使用行情时都重新解析和清洗原始 CSV。

一次清洗结果会生成三个文件：

```text
data/cleaned/
└── 000001.SZ/
    └── 20240101_20241231/
        ├── bars.csv
        ├── rejected.csv
        └── quality_report.json
```

文件用途：

| 文件 | 内容 |
|---|---|
| bars.csv | 标准化后的合法行情 |
| rejected.csv | 被拒绝的原始记录及拒绝原因 |
| quality_report.json | 数据质量统计报告 |

其中：

- `bars.csv` 使用系统内部的 Bar 结构进行序列化。
- `rejected.csv` 保存记录序号、股票代码、交易日期和拒绝原因。
- `quality_report.json` 保存完整的数据质量统计信息。

Storage 同时提供重新加载标准行情和质量报告的能力。

## 4. 核心数据结构

### 4.1 RawTushareBar

表示从 Tushare CSV 中解析出的原始行情。

主要特点：

- 保留 Tushare 原始字段名称。
- 数值字段使用 `Option<f64>`，用于区分字段缺失和有效数值。
- 不在 Parser 阶段进行单位转换。

### 4.2 Bar

系统内部统一的行情数据结构。

```rust
pub struct Bar {
    pub symbol: String,
    pub date: String,
    pub open: f64,
    pub high: f64,
    pub low: f64,
    pub close: f64,
    pub volume: f64,
    pub amount: Option<f64>,
}
```

Bar 是 Data Clean 向回测系统输出的核心数据结构。

它与具体数据源无关，回测引擎不需要知道行情来自 Tushare 还是其他数据提供者。

### 4.3 CleaningResult

表示一次完整的行情清洗结果。

```rust
pub struct CleaningResult {
    pub bars: Vec<Bar>,
    pub rejected: Vec<RejectedRecord>,
    pub quality: DataQualityReport,
}
```

包含三部分：

- `bars`：清洗后可以使用的行情。
- `rejected`：被拒绝的原始记录及原因。
- `quality`：本次清洗的数据质量报告。

### 4.4 DataQualityReport

表示一次数据清洗任务的质量统计结果。

由 Cleaner 在处理数据时持续更新，最终交给 Storage 保存。

## 5. 对外 API

Data Clean 对外提供的接口主要分为清洗、存储和加载三类。

### 5.1 行情清洗入口

```rust
pub fn clean_tushare_file(
    path: impl AsRef<Path>,
) -> Result<CleaningResult, Box<dyn Error>>
```

功能：

读取指定的 Tushare CSV 文件，完成解析、校验、异常检查、标准化、去重和排序。

输入：

- 原始 CSV 文件路径。

输出：

- `CleaningResult`。

错误：

- 文件无法打开。
- CSV Header 无法读取。
- 整体文件读取过程发生无法恢复的错误。

普通记录级别的解析和校验错误会被记录在 `rejected` 中，而不是直接终止整个清洗过程。

### 5.2 保存清洗结果

```rust
pub fn save_cleaning_result(
    result: &CleaningResult,
    output_dir: impl AsRef<Path>,
) -> Result<StoragePaths, Box<dyn Error>>
```

功能：

将一次清洗结果保存为三个文件：

- bars.csv
- rejected.csv
- quality_report.json

输入：

- CleaningResult。
- 输出目录。

输出：

- StoragePaths，包含三个文件的实际路径。

### 5.3 加载标准行情

```rust
pub fn load_cleaned_bars(
    path: impl AsRef<Path>,
) -> Result<Vec<Bar>, Box<dyn Error>>
```

功能：

从已经清洗并保存的行情 CSV 中重新加载标准 Bar 数据。

输入：

- bars.csv 文件路径。

输出：

- `Vec<Bar>`。

该接口可以为回测引擎提供标准化行情数据。

### 5.4 加载质量报告

```rust
pub fn load_quality_report(
    path: impl AsRef<Path>,
) -> Result<DataQualityReport, Box<dyn Error>>
```

功能：

读取已经保存的 JSON 数据质量报告。

输入：

- quality_report.json 文件路径。

输出：

- `DataQualityReport`。

### 5.5 StoragePaths

```rust
pub struct StoragePaths {
    pub bars_path: PathBuf,
    pub rejected_path: PathBuf,
    pub quality_report_path: PathBuf,
}
```

表示一次清洗结果持久化后生成的文件路径。

## 6. 完整数据处理流程

以 Tushare 日线行情为例：

```text
          Tushare
              |
              v
        Acquisition
              |
              v
         Raw CSV
              |
              v
         Raw Storage
              |
              v
           Parser
              |
              v
          Validator
              |
              v
       Anomaly Check
              |
              v
          Normalizer
              |
              v
           Cleaner
              |
       +------+------+
       |             |
       v             v
   Clean Bars    Rejected Records
       |             |
       +------+------+
              |
              v
       Quality Report
              |
              v
           Storage
              |
       +------+------+ 
       |      |      |
       v      v      v
     bars   rejected quality
      CSV     CSV     JSON
       |
       v
     Loader
       |
       v
   Vec<Bar>
       |
       v
 Backtest Engine
```

整个流程实现了原始行情与回测引擎之间的数据隔离：

外部数据源负责提供原始行情，Data Clean 负责转换和规范化，回测引擎只需要消费统一的 Bar 数据。

## 7. 当前版本边界

Data Clean V1 当前主要面向 Tushare A 股日线行情。

已具备：

- Tushare CSV 解析。
- 基础行情合法性校验。
- 初步行情异常检查。
- 日期和计量单位标准化。
- 按股票代码和交易日期去重。
- 数据质量统计。
- 原始数据与清洗数据分离存储。
- 标准行情和质量报告重新加载。

当前尚未实现：

- 多数据源适配。
- 复权因子处理。
- 交易日历完整性检查。
- 基于历史分布的动态异常检测。
- 大文件流式清洗。
- 增量行情更新。
- 数据集版本管理。
- 多股票组合回测的数据组织与处理。

这些功能不属于当前 V1 的必要范围。

**Data Clean V1 的核心目标已经明确：为整个量化系统提供统一、规范、可追踪、可持久化的行情数据。**
